# Backlog

Where the code does not yet match `docs/PATTERNS.md` or `docs/UI.md`. These are
findings, not licences: new work follows those two files. A row leaves when it is
fixed, and a backlog that keeps solved rows stops being read.

**A row is a rollback pointer, not a narrative.** Four cells, none of them
empty: what the gap is, where it lives, what the fix is, and what it is waiting
for. The whole row stays under 600 characters and is written to 575, so the next
edit to a row is an edit rather than a build failure. **Every row names what it
is waiting for** — a row with no trigger is a row nobody can ever retire — and
that rule is now [checked] rather than held by habit: `src/backlog.test.ts`
fails on an empty cell, an over-long row, a struck-through row, or a table it
cannot find.

Reasoning that outgrows a row belongs where such things live: the feature doc
that raised it, `docs/PATTERNS.md` or `docs/UI.md` where it is a general rule,
`docs/SPEC.md` §13 where it is a settled design decision, or a comment at the
code it governs. The rows as they read before they were trimmed are in this
file's own history and in that of `docs/PATTERNS.md` §11 and `docs/UI.md` §12,
whose headings now point here.

Add a row when a review finds a gap it is not fixing in the same pass.
